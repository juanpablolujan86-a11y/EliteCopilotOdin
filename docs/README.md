# Documentación de ODIN

Este directorio es el punto de entrada técnico y funcional para colaboradores.

## Empezar a desarrollar

1. Lea la [arquitectura](ARCHITECTURE.md).
2. Revise las [decisiones arquitectónicas](ArchitectureDecisions.md).
3. Prepare el entorno con la guía de [contribución](../CONTRIBUTING.md).
4. Consulte el [roadmap](ROADMAP.MD) antes de proponer una función nueva.
5. Ejecute toda la suite de pruebas antes de abrir un pull request.

## Qué documentos son históricos

El Captain's Log y el changelog describen decisiones y versiones pasadas; no
son la referencia de la arquitectura actual. Ante una diferencia, prevalecen
`ARCHITECTURE.md`, el código y las pruebas vigentes.
